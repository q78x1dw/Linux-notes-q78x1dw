User: bash $* 和 $@ 什么区别

DeepSeek: 在 Bash 中，`$*` 和 `$@` 的核心区别在于**是否带双引号**。**在不带引号时，两者行为几乎一样；但在带双引号时（即 `"$*"` 与 `"$@"`），它们有本质区别。**

简单记住一句话：**`"$@"` 保留每个参数的原样，`"$*"` 把所有参数粘成一个大字符串。**

为了直观理解，请看以下示例脚本 `test.sh`：

```bash
#!/bin/bash
# 假设我们传入三个参数： "A" "B C" "D"

echo "===== 不加引号 (几乎一样) ====="
for arg in $*; do echo "$arg"; done
echo "---"
for arg in $@; do echo "$arg"; done

echo "===== 加双引号 (核心区别) ====="
echo "使用 \"\$*\":"
for arg in "$*"; do echo "$arg"; done

echo "使用 \"\$@\":"
for arg in "$@"; do echo "$arg"; done
```

执行 `./test.sh A "B C" D`，输出结果如下：

```text
===== 不加引号 (几乎一样) =====
A
B
C
D
---
A
B
C
D
===== 加双引号 (核心区别) =====
使用 "$*":
A B C D          <-- 注意：全部粘成了一整个字符串
使用 "$@":
A                <-- 注意：B C 作为一个整体被保留
B C
D
```

---

### 详细原理解析

#### 1. `"$@"` —— **逐词传递（推荐）**
- 将每个位置参数展开为**独立的、带引号的单词**。
- 等价于 `"$1" "$2" "$3" ...`。
- **最大的优点**：能够完美保留参数中的空格、换行和特殊字符。
- **使用场景**：**99% 的情况下，当你需要传递命令行参数时，都应该使用 `"$@"`**（例如在脚本中转发给其他命令：`grep "$@"`）。

#### 2. `"$*"` —— **合并为单串**
- 将所有位置参数展开为**一个单一的字符串**。
- 参数之间会使用 **`IFS`（内部字段分隔符）** 变量的第一个字符进行连接（默认是空格）。
- **使用场景**：少数情况，比如你需要把所有参数拼接成一个字符串来打印日志，或者传给某个只接受单字符串参数的函数。

#### 3. 不带引号的情况（`$*` 和 `$@`）
- 不带引号时，两者都会经历“通配符扩展”和“单词拆分”（Word Splitting）。
- 在上面的例子中，`"B C"` 被拆成了 `B` 和 `C`，所以二者输出看起来一样。
- **强烈不推荐**直接使用不带引号的 `$@` 或 `$*`，因为如果参数包含空格或 `*` 号，会导致逻辑错误。

---

### 进阶：改变 IFS 影响 `"$*"`
既然 `"$*"` 用 IFS 连接，你可以修改 IFS 来改变拼接结果：

```bash
#!/bin/bash
# 执行 ./test.sh a b c
IFS=,
echo "$*"   # 输出：a,b,c

IFS='|'
echo "$*"   # 输出：a|b|c
```

### 总结速查表

| 写法 | 是否拆分 | 结果示例（参数为 `a "b c" d`） | 推荐度 |
| :--- | :--- | :--- | :--- |
| `$*` | 是 | `a`, `b`, `c`, `d`（空格被拆） | ❌ 不推荐 |
| `$@` | 是 | `a`, `b`, `c`, `d`（空格被拆） | ❌ 不推荐 |
| **`"$*"`** | **否（合并）** | **`"a b c d"`（一个整体）** | ⚠️ 特定场景 |
| **`"$@"`** | **否（保留边界）** | **`"a"` `"b c"` `"d"`（保留原样）** | ✅ **强烈推荐** |

**最佳实践**：如果你在写脚本要转发参数，永远记得加上双引号和 `@`——写成 **`"$@"`**。这是 Bash 编程中少数的“银弹”规则之一。
