# Bash花括号模式匹配

## User

bash中的{}在模式匹配有什么用

## DeepSeek

在 Bash 中，`{}`（花括号）在“模式匹配”语境下主要有**两种完全不同的用途**，很容易混淆。你需要根据它出现的位置来判断：

### 1. 在大括号展开（Brace Expansion）中——生成匹配模式
这是 `{}` 最常见的用法。它**不是**标准的通配符（如 `*` 或 `?`），而是在命令执行**之前**由 Shell 自动展开生成字符串列表。常用于批量操作。

- **逗号分隔枚举**：`{a,b,c}` 展开为 `a b c`。
- **数值/字母范围**：`{1..5}` 展开为 `1 2 3 4 5`；`{a..z}` 展开为 a 到 z。
- **组合嵌套**：`{a,b}{1,2}` 展开为 `a1 a2 b1 b2`。

**在“模式匹配”中的实战用法（结合 `ls`、`cp`、`rm`）：**

- **批量匹配文件名**：`ls *.{jpg,png}` 会展开为 `ls *.jpg *.png`，然后 Shell 再将 `*.jpg` 和 `*.png` 分别交给 `ls` 去匹配实际存在的文件。
- **利用范围匹配**：`rm file_{1..10}.log` 会展开为 `rm file_1.log file_2.log ... file_10.log`。

> **关键区别**：`*.{txt,csv}` 是先展开成两个独立的通配符，再去匹配文件；如果没有任何文件匹配，`*.txt` 会原样保留，而不是像 `[]` 那样只匹配单字符。

---

### 2. 在参数展开（Parameter Expansion）中——匹配并操作字符串
当 `{}` 紧跟在 `$` 符号后面（即 `${var}`）时，它用于变量边界界定，并支持内部进行**字符串模式匹配**（这才是真正的“匹配并处理”）。

| 语法 | 作用（模式匹配） | 示例（假设 `file="photo_2026.jpg"`） |
| :--- | :--- | :--- |
| `${var#模式}` | **从头**删除**最短**匹配 | `echo ${file#*_}` 输出 `2026.jpg`（删掉 `photo_`） |
| `${var##模式}` | **从头**删除**最长**匹配 | `echo ${file##*.}` 输出 `jpg`（提取后缀） |
| `${var%模式}` | **从尾**删除**最短**匹配 | `echo ${file%.*}` 输出 `photo_2026`（删掉 `.jpg`） |
| `${var%%模式}` | **从尾**删除**最长**匹配 | `echo ${var%%_*}` 输出 `photo`（提取前缀） |
| `${var/模式/替换}` | 替换**第一个**匹配的字符串 | `echo ${file/jpg/png}` 输出 `photo_2026.png` |
| `${var//模式/替换}` | 替换**所有**匹配的字符串 | `echo ${var//_/-}` 将 `_` 全部替换为 `-` |

> **注意**：这里的“模式”支持通配符（`*` 代表任意字符，`?` 代表单字符），但不能使用正则表达式。

---

### 3. 一个极易踩的坑：通配符（Glob）中的 `{}` vs `[]`
- `[]`（方括号）：匹配**一个**字符。例如 `file[0-9].txt` 只匹配 `file0.txt` 到 `file9.txt`。
- `{}`（花括号）：生成**多个**独立的词。例如 `file{0,1,2}.txt` 等价于 `file0.txt file1.txt file2.txt`。

**陷阱示例**：
如果当前目录没有 `file1.txt`，执行 `ls file{1,2}.txt`：
- Shell 先展开为 `ls file1.txt file2.txt`。
- `ls` 发现 `file1.txt` 不存在，会报错“No such file or directory”，但依然会尝试列出 `file2.txt`。

**总结一句话**：`{}` 在**命令行输入**时用于“造词/批量生成模式”；在 **`${}` 变量内部**时用于“按通配符模式截取或替换内容”。前者是壳（Shell）的语法糖，后者是变量的字符串处理工具。如果你是想用正则表达式匹配，`{}` 在 Bash 原生模式中并不支持（需要用到 `grep -E` 或 `[[ =~ ]]`）。如果你遇到了具体报错，可以发出来帮你排查。
